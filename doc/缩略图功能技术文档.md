>
> **核心要点：**
> - 缩略图采用 **后端异步生成 + 前端轮询加载** 的架构，不依赖 Socket.io 事件即可工作。
> - 缓存路径为 `%LOCALAPPDATA%\Temp\SVFPcache`（Electron 下为 `app.getPath('temp')/SVFPcache`）。

> - 缩略图质量支持三档可调（低/中/高），通过 `JPEG_QUALITY` 映射控制 ffmpeg `-q:v` 参数。
> - 缩略图数量可配置范围为 1-5（默认 3），在列表视图中仅显示第一张，点击可打开 Lightbox 浏览全部。
> - 应用启动时自动清理旧缓存，设置页面提供手动清除缓存功能。

## 1. 功能概述

### 1.1 用途

缩略图功能为视频文件批量处理工具提供视频预览能力。用户在"工作台"页面点击"加载"按钮扫描视频目录后，系统自动为每个视频文件生成缩略图，并在文件列表中展示，帮助用户快速识别视频内容。

### 1.2 核心价值

- **快速预览**：无需打开视频文件即可在列表中预览视频内容
- **批量处理辅助**：在设置 Tag 标签时，缩略图帮助用户确认视频内容，减少误操作
- **多帧预览**：支持每个视频生成 1-5 张缩略图（默认 3 张），帧位置基于视频时长均匀分布

### 1.3 应用场景

- 工作台批量处理：加载视频目录后，在缩略图视图中为每个文件设置 Tag
- 内容审核：通过缩略图快速判断视频内容类型
- 文件整理：配合 Tag 标签和目标路径，实现视频文件的自动分类移动

### 2.2 设计原则

1. **前端不依赖 Socket.io**：缩略图 URL 可通过 `videoHash` 直接构造，Socket.io 的 `thumbnail:ready` 事件仅作为辅助通知（当前版本前端已不再监听该事件）。
2. **后端异步生成**：`POST /api/scan` 先返回文件列表，缩略图在后台异步生成，不阻塞用户操作。
3. **缓存复用**：同一视频的缩略图只生成一次，后续加载直接使用缓存。
4. **自动清理**：应用启动时自动清理上次运行遗留的缓存文件。

### 3.4 ThumbnailImg 组件

**核心机制：轮询重试加载**

```typescript
function ThumbnailImg({ videoHash, index, onClick }: {
  videoHash?: string;
  index: number;
  thumbnailCount: number;
  onClick?: () => void;  // 点击回调，仅当 thumbnailCount > 1 时传入
})
```

**URL 构造规则：**
```
API_BASE.replace('/api', '') + '/api/thumbnail-files/' + videoHash + '/' + (index + 1) + '.jpg'
// 示例: http://localhost:3000/api/thumbnail-files/2153e1bac083a3a6/1.jpg
```

**重试策略：**
- 最大重试次数：20 次
- 重试间隔：`1000ms + retryCount × 500ms`（1s → 1.5s → 2s → 2.5s → ...）
- 每次重试通过更新 `key` 属性（`key={videoHash}-{index}-{retryCount}`）强制浏览器发起新请求
- 达到最大重试次数后显示错误图标（播放按钮占位符）

**四种状态：**

| 状态 | 条件 | UI 表现 |
|------|------|---------|
| 等待中 | `videoHash` 为空 | 转圈动画 |
| 加载中 | 图片请求中（未 loaded 且未 error） | 转圈动画叠加层 |
| 已加载 | `onLoad` 触发 | 显示缩略图，`cursor: pointer`（如有 onClick） |
| 错误 | 重试 20 次后仍失败 | 播放按钮占位图标 |

**点击交互：**
- 当 `thumbnailCount > 1` 时，传入 `onClick` 回调 → 鼠标悬停显示手型光标
- 当 `thumbnailCount === 1` 时，不传 `onClick` → 缩略图不可点击

### 4.2 缓存路径

```typescript
export function getThumbnailDir(): string {
  try {
    // Electron 环境：使用系统 Temp 目录
    const electronApp = require('electron').app;
    return path.join(electronApp.getPath('temp'), 'SVFPcache');
  } catch {
    // 独立服务器：使用 %LOCALAPPDATA%\Temp\SVFPcache
    const localAppData = process.env.LOCALAPPDATA || process.env.TEMP || process.env.TMP || '';
    if (localAppData) {
      return path.join(localAppData, 'Temp', 'SVFPcache');
    }
    // 兜底：项目目录下的 data/thumbnails
    return path.resolve('data/thumbnails');
  }
}
```

**路径示例：**
- Windows Electron：`C:\Users\[用户名]\AppData\Local\Temp\SVFPcache\`
- Windows 独立服务器：`C:\Users\[用户名]\AppData\Local\Temp\SVFPcache\`

### 4.3 videoHash 计算

```typescript
export function computeVideoHash(filePath: string): string {
  const hash = crypto.createHash('sha256');
  hash.update(filePath);
  return hash.digest('hex').slice(0, 16);
}
```

- 使用文件路径（非文件内容）的 SHA256 哈希前 16 位
- 同一文件路径始终映射到同一 hash，实现缓存复用
- 16 位 hex 提供 2^64 种可能，碰撞概率极低

### 4.4 缩略图生成流程

```
generateThumbnailsForVideo(videoPath, fileId, count, options?)
    │
    ├── ① 检查视频文件是否存在
    │
    ├── ② computeVideoHash(videoPath) → videoHash
    │
    ├── ③ 创建缓存目录 {thumbDir}/{videoHash}/
    │
    ├── ④ 查找 ffmpeg 可执行文件
    │
    ├── ⑤ 解析质量参数（options.quality → q:v 值）
    │
    └── ⑥ 循环生成 count 张缩略图:
         for i = 1 to count:
           ├── 计算帧位置（基于视频时长均匀分布）
           │     seekSeconds = i × duration / (count + 1)    [count > 1]
           │     seekSeconds = duration / 2                  [count = 1]
           │     seekSeconds = i                             [无时长信息时回退]
           │     最小值为 1s（避免开头黑帧）
           ├── 检查缓存是否存在 → 命中则跳过
           └── 调用 ffmpeg:
               ffmpeg -ss {seekSeconds} -i {videoPath} -frames:v 1 -q:v {quality}
                      -vf scale=320:180:force_original_aspect_ratio=decrease,
                          pad=320:180:(ow-iw)/2:(oh-ih)/2:black
                      -y {outputPath}
```

**ffmpeg 参数说明：**

| 参数 | 值 | 说明 |
|------|-----|------|
| `-ss` | 动态计算 | 基于视频时长均匀分布的帧位置（秒），最小 1s |
| `-frames:v` | `1` | 只截取 1 帧 |
| `-q:v` | `2` / `5` / `12` | JPEG 质量（2-31，越小质量越高），由缩略图质量设置控制 |
| `-vf scale` | `320:180` | 缩放到 320×180，保持宽高比 |
| `-vf pad` | `320:180` | 填充黑边到目标尺寸 |
| `-y` | — | 覆盖已存在的输出文件 |
| `timeout` | `15000ms` | 单个 ffmpeg 进程超时时间 |

**默认参数：**
- 宽度：320px
- 高度：180px
- JPEG 质量：5（对应"中"质量档位）
- 超时：15 秒

**帧位置均匀分布算法：**

| 场景 | 公式 | 示例（60s 视频，3 张） |
|------|------|----------------------|
| count > 1 | `i × duration / (count + 1)` | 15s, 30s, 45s |
| count = 1 | `duration / 2` | 30s（视频中间） |
| duration = 0 | `i`（秒） | 1s, 2s, 3s（回退） |

**JPEG 质量映射表（QUALITY_MAP）：**

| 档位 | q:v 值 | 效果 |
|------|--------|------|
| `low` | `12` | 高压缩率，文件小，质量较低 |
| `medium` | `5` | 均衡，默认值 |
| `high` | `2` | 低压缩率，文件大，质量最高 |

### 4.5 缓存管理

**启动清理（`cleanupOldThumbnails`）：**
- 在 `server.ts` 和 `electron/main.ts` 的启动流程中调用
- 删除 `SVFPcache` 目录下所有子文件夹
- 确保每次启动时缓存是干净的

**获取缓存大小（`getThumbnailCacheSize`）：**
- 递归遍历 `SVFPcache` 目录
- 累加所有 `.jpg` 文件的大小
- 返回总字节数

**清除缓存（`clearThumbnailCache`）：**
- 删除 `SVFPcache` 目录下所有子文件夹
- 返回删除的文件夹数量

### 4.6 ffmpeg 检测与持久化

- 首次启动时自动检测系统 PATH 中的 ffmpeg
- 用户在设置页面指定 bin 路径后，调用 `POST /api/ffmpeg/detect` 检测
- 检测结果持久化到 SQLite `tbl_settings` 表：
  - `ffmpegAvailable`：是否可用
  - `ffmpegVersion`：版本号
  - `ffmpegPath`：可执行文件路径
  - `ffmpegBinPath`：用户指定的 bin 目录
- 内存缓存（`cachedFfmpegInfo`）避免重复检测

### 4.7 缩略图配置持久化

以下设置项通过 `POST /api/settings/:key` 持久化到 SQLite `tbl_settings` 表：

| 设置键 | 默认值 | 说明 |
|--------|--------|------|
| `thumbnailCount` | `'3'` | 每个视频生成缩略图数量（1-5） |
| `thumbnailQuality` | `'medium'` | 缩略图质量档位（low/medium/high） |

- `flows.ts` 在 scan 时实时读取，确保最新设置立即生效
- 前端设置页面修改后通过 API 保存，不需要重启应用

## 5. 接口说明

### 5.1 缩略图静态文件服务

**GET `/api/thumbnail-files/:videoHash/:filename`**

获取已生成的缩略图文件。

| 项目 | 说明 |
|------|------|
| 方法 | `GET` |
| 路径参数 | `videoHash` — 16 位 hex 字符串；`filename` — `{序号}.jpg` |
| 参数校验 | `videoHash` 必须匹配 `/^[\da-f]{16}$/`；`filename` 必须匹配 `/^\d+\.jpg$/` |
| 成功响应 | `200` — 返回 JPEG 图片二进制流 |
| 失败响应 | `400` — 参数格式错误；`404` — 文件不存在 |

**请求示例：**
```
GET /api/thumbnail-files/2153e1bac083a3a6/1.jpg
```

## 6. 部署说明

### 6.1 环境要求

| 依赖 | 版本/说明 |
|------|-----------|
| Node.js | ≥ 18.x |
| FFmpeg | 任意版本（需在 PATH 中或手动配置路径） |
| 操作系统 | Windows（缓存路径使用 `%LOCALAPPDATA%`） |

### 6.2 FFmpeg 配置

1. **自动检测**：应用启动时自动搜索系统 PATH 中的 `ffmpeg`/`ffmpeg.exe`
2. **手动配置**：在设置 → FFmpeg 设置中输入 `ffmpeg.exe` 所在目录，点击"检测"
3. **持久化**：检测结果自动保存到 SQLite，下次启动无需重新检测

### 6.3 缓存目录

- **位置**：`C:\Users\[用户名]\AppData\Local\Temp\SVFPcache\`
- **自动清理**：每次应用启动时自动删除旧缓存
- **手动清理**：设置 → FFmpeg 设置 → 点击"清除缓存"
- **系统清理**：Windows 磁盘清理工具可识别 Temp 目录下的文件

### 6.4 构建步骤

```bash
# 1. 编译后端
npx tsc

# 2. 编译前端
cd web && npm run build

# 3. 启动（开发模式）
npm run electron:dev

# 4. 打包
npm run electron:build
```

## 7. 常见问题及解决方案

### 7.1 缩略图无限转圈

**现象：** 前端文件列表加载成功，但缩略图区域一直显示转圈动画。

**排查步骤：**

1. **检查后端日志**：确认 `[thumbnail] generated` 日志出现
2. **检查缓存目录**：确认 `%LOCALAPPDATA%\Temp\SVFPcache\{hash}\1.jpg` 文件存在
3. **检查静态文件服务**：浏览器直接访问 `http://localhost:3000/api/thumbnail-files/{hash}/1.jpg`
4. **检查 videoHash**：确认 scan 响应中包含 `videoHash` 字段
5. **检查前端 URL 构造**：确认 `API_BASE` 正确（Electron 中可能不是 `localhost:3000`）

**常见原因：**
- FFmpeg 未安装或未检测到 → 检查设置页面的 FFmpeg 状态
- 缓存目录权限不足 → 检查 `%LOCALAPPDATA%\Temp\` 目录权限
- `API_BASE` 配置错误 → Electron 环境下需确认端口号
- 视频文件损坏 → ffmpeg 无法读取，检查后端日志中的 ffmpeg 错误

### 7.2 FFmpeg 检测失败

**现象：** 设置页面显示"未检测到"。

**解决方案：**
1. 确认 `ffmpeg.exe` 存在于指定目录
2. 尝试将 FFmpeg bin 目录添加到系统 PATH
3. 检查 `tbl_settings` 表中的 `ffmpegBinPath` 是否正确
4. 调用 `POST /api/ffmpeg/detect` 手动触发检测

### 7.3 缓存占用过大

**现象：** 缓存目录占用大量磁盘空间。

**解决方案：**
1. 在设置页面点击"清除缓存"
2. 应用每次启动时会自动清理旧缓存
3. 可使用 Windows 磁盘清理工具清理 Temp 目录

### 7.4 NODE_MODULE_VERSION 不匹配

**现象：** 启动时报 `better_sqlite3.node was compiled against a different Node.js version`。

**解决方案：**
```bash
# 独立服务器模式
npm rebuild better-sqlite3

# Electron 模式
npx @electron/rebuild
```

### 7.5 缩略图生成超时

**现象：** 后端日志显示 `ffmpeg error` 或超时。

**原因：** 大视频文件（如 2GB+）的 ffmpeg 处理时间超过 15 秒。

**解决方案：** 当前超时设置为 15 秒，对于超大文件可能需要调整 `src/utils/thumbnail.ts` 中的 `timeout: 15000` 参数。

### 7.6 缩略图显示为黑色

**现象：** 缩略图加载成功但显示为纯黑色。

**原因：** 视频开头几秒可能为黑屏过渡。

**解决方案：** 当前已使用基于视频时长的均匀分布算法，帧位置最小值为 1s（`Math.max(1, ...)`），可有效避免开头黑帧问题。如仍有问题，可在 `src/utils/thumbnail.ts` 中调整 `Math.max(1, ...)` 的起始偏移量。
