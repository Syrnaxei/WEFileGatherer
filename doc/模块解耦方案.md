> 版本：1.0 | 最后更新：2026-05-17

本文档记录了将"工作台"模块中的三个核心功能（缩略图生成、文件属性获取、缩略图缩放交互）解耦为独立可复用组件的完整方案。解耦后，这些功能同时服务于"工作台"和"搜刮"两个模块，消除了代码重复，保证了功能一致性和用户体验统一性。

## 一、缩略图生成功能解耦

### 1.1 背景

原有实现中，`POST /api/scan` 路由内部直接包含缩略图生成的完整逻辑（读取设置、调用 ffmpeg、发送 Socket.io 事件）。搜刮模块的 `/scrape/scan` 路由需要相同的缩略图能力，但代码完全独立编写。解耦目标是将缩略图异步生成逻辑抽取为共享函数，两个路由统一调用。

### 1.2 核心实现

#### 共享函数：`startThumbnailGeneration()`

**文件位置：** [src/api/flows.ts](file:///e:/AAAProject/VideoFileProcessing/src/api/flows.ts)

```typescript
async function startThumbnailGeneration(
  files: { filePath: string; fileName: string; duration: number }[],
  logPrefix: string
)
```

**参数说明：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `files` | `Array<{filePath, fileName, duration}>` | 需要生成缩略图的视频文件列表 |
| `logPrefix` | `string` | 日志前缀，用于区分调用来源（`'Scan'` / `'ScrapeScan'`） |

**执行流程：**

1. 调用 `getFfmpegInfo()` 检查 ffmpeg 是否可用，不可用则跳过并输出警告
2. 从 SQLite 读取设置：`thumbnailCount`（默认 3）、`thumbnailQuality`（默认 `'medium'`）
3. 通过 `getQualityDimensions()` 获取质量对应分辨率
4. 遍历文件列表，为每个文件调用 `generateThumbnailsForVideo()` 异步生成缩略图
5. 生成完成后通过 Socket.io 发送 `thumbnail:ready` 事件，通知前端更新

**调用位置：**

- **工作台** — [flows.ts `POST /api/scan`](file:///e:/AAAProject/VideoFileProcessing/src/api/flows.ts)：列表视图模式下跳过（`viewMode === 'list'`）
- **搜刮** — [flows.ts `POST /api/scrape/scan`](file:///e:/AAAProject/VideoFileProcessing/src/api/flows.ts)：始终触发生成

### 1.3 底层依赖

缩略图底层工具函数位于 [src/utils/thumbnail.ts](file:///e:/AAAProject/VideoFileProcessing/src/utils/thumbnail.ts)，本次解耦未修改该文件：

| 函数 | 作用 |
|------|------|
| `getFfmpegInfo()` | 检测 ffmpeg/ffprobe 是否可用 |
| `getQualityDimensions()` | 将质量等级（low/medium/high）映射为分辨率 |
| `generateThumbnailsForVideo()` | 基于 ffmpeg 为单个视频生成缩略图帧 |
| `computeVideoHash()` | 基于文件路径 SHA256 计算视频唯一标识 |

### 1.4 设置依赖

`startThumbnailGeneration()` 从 SQLite `tbl_settings` 表读取以下配置：

| 设置项 | 键名 | 默认值 | 说明 |
|--------|------|--------|------|
| 缩略图数量 | `thumbnailCount` | `3` | 每个视频生成的缩略图帧数（1-5） |
| 缩略图质量 | `thumbnailQuality` | `medium` | 三档可选：low / medium / high |

## 二、文件属性获取功能解耦

### 2.1 背景

原有实现中，文件属性（文件大小、视频时长、码率）的获取逻辑分散在各 API 路由中，字段命名和处理方式不一致。解耦目标是将属性探测抽离为独立工具模块，同时在前端提供统一的格式化函数。

### 2.2 后端实现

#### 核心模块：`src/utils/probe.ts`

**文件位置：** [src/utils/probe.ts](file:///e:/AAAProject/VideoFileProcessing/src/utils/probe.ts)

**导出接口：**

```typescript
export interface VideoProbeResult {
  fileSize: number;  // 文件大小（字节）
  duration: number;  // 视频时长（秒）
  bitrate: number;   // 视频码率（bps）
}
```

**核心函数：`probeVideoFile()`**

```typescript
export async function probeVideoFile(
  filePath: string,
  ffprobeCmd?: string | null
): Promise<VideoProbeResult>
```

**执行逻辑：**

1. **文件大小** — 使用 `fs.stat()` 获取字节数。失败时返回 0，不中断流程
2. **视频时长和码率** — 仅当 `ffprobeCmd` 可用时调用。通过 `execFile` 执行 ffprobe，参数为 `-v quiet -print_format json -show_format -show_streams`，超时时间 10 秒。从返回 JSON 的 `format.duration` 和 `format.bit_rate` 提取数据。失败时返回 0
3. 所有错误均静默处理（`catch {}`），确保单文件探测失败不影响批量扫描

**辅助函数：`resolveFfprobeCmd()`**

```typescript
export async function resolveFfprobeCmd(binPath?: string): Promise<string | null>
```
从设置中的自定义 bin 路径或系统 PATH 查找 ffprobe，返回可执行命令或 null。

#### 调用方式

两个 API 路由均采用相同模式：

```typescript
const ffprobeCmd = await resolveFfprobeCmd(db.getSetting('ffmpegBinPath') || undefined);

const files = await Promise.all(videoEntries.map(async (entry) => {
  const probe = await probeVideoFile(filePath, ffprobeCmd);
  return {
    id: randomUUID(),
    fileName: entry.name,
    filePath,
    // ...
    fileSize: probe.fileSize,
    duration: probe.duration,
    bitrate: probe.bitrate,
    videoHash: computeVideoHash(filePath),
  };
}));
```

`Promise.all` 保证所有文件属性并行获取，最大化 I/O 吞吐。

### 2.3 前端实现

#### 格式化工具：`web/src/utils/format.ts`

**文件位置：** [web/src/utils/format.ts](file:///e:/AAAProject/VideoFileProcessing/web/src/utils/format.ts)

| 函数 | 输入 | 输出示例 | 说明 |
|------|------|----------|------|

## 三、缩略图缩放交互功能解耦

### 3.1 背景

原有实现中，缩略图显示（`ThumbnailImg`）和图片查看器（`ThumbnailLightbox`）的代码直接内联在 [FileList.tsx](file:///e:/AAAProject/VideoFileProcessing/web/src/components/FileList.tsx) 中。解耦目标是将这两个组件提取为独立文件，使其可被 FileList 和 ScrapePage 共同使用。

### 3.2 ThumbnailImg 组件

**文件位置：** [web/src/components/ThumbnailImg.tsx](file:///e:/AAAProject/VideoFileProcessing/web/src/components/ThumbnailImg.tsx)

**Props 接口：**

```typescript
export interface ThumbnailImgProps {
  videoHash?: string;       // 视频哈希标识，用于构造缩略图 URL
  index: number;            // 缩略图索引（0-based）
  thumbnailCount: number;   // 缩略图总数（保留参数，当前未使用）
  onClick?: () => void;     // 点击回调，传入时显示 pointer 光标
}
```

**状态与行为：**

| 特性 | 实现 |
|------|------|
| URL 构造 | `/api/thumbnail-files/{videoHash}/{index + 1}.jpg` |
| 轮询重试 | 最多 20 次，首次间隔 1000ms，逐次递增 500ms |
| 加载状态 | 居中旋转加载动画（CSS animation `spin`） |
| 错误状态 | 视频播放图标占位（SVG polygon） |
| 无 hash 状态 | 加载动画占位，与加载中视觉一致 |
| 样式 | 全部使用 CSS 变量（`var(--bg-surface-3)`、`var(--accent)` 等） |

### 3.3 ThumbnailLightbox 组件

**文件位置：** [web/src/components/ThumbnailLightbox.tsx](file:///e:/AAAProject/VideoFileProcessing/web/src/components/ThumbnailLightbox.tsx)

**Props 接口：**

```typescript
export interface ThumbnailLightboxProps {
  videoHash: string;                    // 视频哈希标识
  thumbIndex: number;                   // 当前查看的缩略图索引
  thumbnailCount: number;               // 缩略图总数
  onClose: () => void;                  // 关闭回调
  onNavigate: (direction: -1 | 1) => void;  // 切换回调
}
```

**交互功能清单：**

| 功能 | 实现方式 | 细节 |
|------|----------|------|
| 键盘关闭 | `Escape` 键 | `document.addEventListener('keydown')` |
| 键盘切换 | `ArrowLeft` / `ArrowRight` | 通过 `onNavigate` 回调通知父组件 |
| 滚轮缩放 | `wheel` 事件 | 范围 1x ~ 3x，步进 0.1，`passive: false` |
| 缩放缓存 | `zoomCache` ref | 以 `thumbIndex` 为键，切换图片时恢复之前的缩放比例 |
| 鼠标边缘感应 | `onMouseMove` | 鼠标靠近窗口边缘 8% 区域时显示切换箭头 |
| 箭头位置 | 固定在窗口左右边缘 | `left: 12px` / `right: 12px`，垂直居中 |
| 缩放复位 | 按钮 | 缩放不为 1x 时显示"复位"按钮 |
| 页码指示 | 底部居中 | 格式 `{当前} / {总数}` |
| 缩放百分比 | 底部居中 | 格式 `{百分比}%` |
| 图片最大尺寸 | 窗口的 1/2 | `maxW = window.innerWidth / 2`，`maxH = window.innerHeight / 2` |
| 点击背景关闭 | `onClick={onClose}` 在外层容器 | 图片区域 `e.stopPropagation()` 阻止冒泡 |

**组件生命周期：**

```
挂载 → 注册键盘事件 → 加载图片 → 用户交互（缩放/切换）
                                    ↓
                              拇指索引变化
                                    ↓
                          zoomCache 读取/写入
                                    ↓
                          关闭 → 移除键盘事件
```

## 六、关键设计决策

### 6.1 后端异步缩略图生成

缩略图生成在 API 响应返回**之后**异步执行，而非阻塞在请求中。原因：
- 缩略图生成耗时较长（每个视频 1-3 秒），阻塞会导致 API 超时或前端长时间等待
- 通过 Socket.io 事件推送生成结果，前端可实时更新，用户体验更好
- 即使缩略图生成全部失败，文件列表和 Tag 分配功能仍可正常使用

### 6.2 前端轮询重试而非 Socket.io 依赖

`ThumbnailImg` 组件使用 HTTP 轮询重试（最多 20 次）加载缩略图，而非完全依赖 Socket.io。原因：
- Socket.io 可能因网络波动丢包，轮询提供兜底保障
- 组件可在无 Socket.io 连接的场景（如直接 HTTP 访问）仍正常工作
- 递增间隔（1000ms + retryCount × 500ms）避免对服务器造成过大压力

### 6.3 缩放状态缓存于会话内

`ThumbnailLightbox` 的 `zoomCache` 使用 `useRef` 存储，不持久化。原因：
- 用户在同一次查看会话中切换图片时保持缩放状态，操作连贯
- 关闭查看器后缓存自然释放，符合"会话内有效"的交互预期
- 避免不必要的数据持久化和清理逻辑
