# 视频缩略图功能设计

## 概述

为 FileList 中的每个视频文件生成缩略图预览，采用后端 ffmpeg 提取帧 + 磁盘缓存的方案。支持单张或多张缩略图（1-10），用户可在高级设置中配置数量。

## 架构

```
前端 <img src="/api/thumbnail?file=xxx.mp4&seek=1">
  ↓
GET /api/thumbnail (src/api/thumbnail.ts)
  ↓
generateThumbnail() (src/utils/thumbnail.ts)
  ↓
缓存命中? → 直接返回 JPEG
缓存未命中? → ffmpeg -ss Ns -i video -frames:v 1 -q:v 5 → 写入缓存 → 返回 JPEG
```

多缩略图场景下，前端为每个 seek 位置（1s, 2s, ...）分别请求 `/api/thumbnail?file=...&seek=N`。

## API 接口

### `GET /api/thumbnail`

获取视频文件在指定时间点的缩略图。

**Query 参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `file` | string | ✅ | - | 视频文件的绝对路径 |
| `width` | number | ❌ | 320 | 缩略图宽度（px） |
| `height` | number | ❌ | 180 | 缩略图高度（px） |
| `seek` | number | ❌ | 1 | 截取位置（秒） |

**响应：**

- `200` — 返回 JPEG 图片（`Content-Type: image/jpeg`）
- `400` — 缺少 `file` 参数
- `500` — 视频文件不存在 / ffmpeg 执行失败
- `503` — 系统未安装 ffmpeg

**示例：**

```
GET /api/thumbnail?file=D%3A%5CVideos%5Cmovie.mp4
GET /api/thumbnail?file=D%3A%5CVideos%5Cmovie.mp4&width=160&height=90&seek=3
```

### `GET /api/thumbnails`

批量获取视频文件在多个时间点的缩略图 URL 列表。

**Query 参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `file` | string | ✅ | - | 视频文件的绝对路径 |
| `count` | number | ❌ | 1 | 缩略图数量（1-10） |
| `width` | number | ❌ | 320 | 缩略图宽度（px） |
| `height` | number | ❌ | 180 | 缩略图高度（px） |

**响应：**

```json
{
  "success": true,
  "urls": [
    "/api/thumbnail?file=...&seek=1&width=160&height=90",
    "/api/thumbnail?file=...&seek=2&width=160&height=90",
    null
  ]
}
```

`urls` 数组长度等于 `count`，生成失败的条目为 `null`。

**错误响应：**

- `400` — 缺少 `file` 参数
- `500` — 视频文件不存在 / ffmpeg 执行失败

## 缓存策略

- **缓存目录**：`data/thumbnails/`（standalone）或 `app.getPath('userData')/thumbnails/`（Electron）
- **缓存键**：`SHA256(文件路径 + 文件大小 + 修改时间).slice(0, 16)`
- **缓存格式**：JPEG（`{cacheKey}.jpg`）
- **缓存失效**：文件大小或修改时间变化时自动重新生成
- **无需手动清理**：旧缓存文件不会自动删除，但不会命中（cacheKey 不同）
- **注意**：当前缓存键不包含 `seek` 参数，不同 seek 位置的缩略图会覆盖同一缓存文件。如需缓存多张不同位置的缩略图，需将 seek 纳入缓存键计算

## ffmpeg 参数

```bash
ffmpeg -ss {seekSeconds} -i {videoPath} -frames:v 1 -q:v 5 \
  -vf "scale=320:180:force_original_aspect_ratio=decrease,pad=320:180:(ow-iw)/2:(oh-ih)/2:black" \
  -y {outputPath}
```

| 参数 | 说明 |
|------|------|
| `-ss` | 跳转到指定秒数（放在 -i 前以加速 seek） |
| `-frames:v 1` | 只提取一帧 |
| `-q:v 5` | JPEG 质量（2=最好，31=最差，5=良好平衡） |
| `-vf scale+pad` | 等比缩放并居中填充黑边 |
| `-y` | 覆盖已有文件 |
| 超时 | 15 秒 |

## ffmpeg 检测

启动时不检测 ffmpeg，仅在首次请求缩略图时检测。检测逻辑：
1. 依次尝试执行 `ffmpeg -version` 和 `ffmpeg.exe -version`
2. 5 秒超时
3. 均失败则返回 `503` + `ffmpeg not found in PATH`

## 文件结构

| 文件 | 说明 |

## 前端集成

### 已实现功能

1. **缩略图视图**：FileList 支持缩略图视图和列表视图两种模式
2. **左图右文布局**：缩略图视图采用左图右文复合布局，左侧缩略图、右侧文件名+属性
3. **视图切换**：ViewToggle 组件支持缩略图/列表视图切换，偏好通过 `fileListViewMode` 设置持久化
4. **懒加载**：`<img>` 使用 `loading="lazy"` 懒加载
5. **加载状态**：缩略图加载中显示旋转加载指示器
6. **错误降级**：加载失败时显示视频播放图标占位符
7. **多缩略图**：根据 `thumbnailCount` 配置（1-10），在缩略图视图中并排显示多张缩略图
8. **文件元数据**：扫描时通过 ffprobe 提取文件大小、码率、时长信息

### 缩略图组件

- **ThumbnailImg**：单张缩略图组件，支持 `seek` 参数指定截取位置
  - 加载中：旋转动画指示器
  - 加载失败：视频播放图标占位符
  - 加载成功：`<img>` 展示缩略图
- **ViewToggle**：视图切换控件，缩略图/列表两种模式
- **ThumbnailView**：缩略图视图，支持单张或多张缩略图并排显示

### 缩略图数量配置

- **设置路径**：高级设置 → 缩略图数量
- **取值范围**：1-10
- **持久化**：通过 `POST /api/settings/thumbnailCount` 保存到 SQLite
- **前端读取**：App.tsx 初始化时从 `GET /api/settings/thumbnailCount` 读取
- **实时生效**：修改后立即影响 FileList 缩略图列宽和显示数量

### 缩略图列宽计算

- 单张缩略图（thumbnailCount = 1）：列宽 80px，高度 45px
- 多张缩略图（thumbnailCount > 1）：列宽 = `thumbnailCount × 72 + (thumbnailCount - 1) × 4` px，高度 40px
- 每张缩略图通过 `seek` 参数分别请求不同时间点（1s, 2s, 3s, ...）

## 注意事项

- ffmpeg 必须在系统 PATH 中可用
- 大文件首次生成缩略图可能需要数秒
- Electron 打包时需考虑 ffmpeg 的分发方式（静态二进制 / 系统依赖）
- 缩略图生成是异步的，不会阻塞主线程
- 当前缓存键不含 seek 参数，多缩略图场景下不同时间点的缓存可能互相覆盖（后续可优化）
- 多缩略图会增加 ffmpeg 调用次数，建议在低配环境下使用较少的缩略图数量
